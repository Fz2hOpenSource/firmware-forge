# 验证协议是否能退出

按当前需求与实际机制选择用例。同步有界的小操作不必具备异步请求表；
没有取消、持久化或并发需求时，不为填满矩阵而补造这些机制。
需要有限图结构检查时，读取 [工具格式](state-model-format.md)。

## 将每个失败变成可重放序列

用虚拟时钟和可注入 adapter 做逻辑测试：输入明确事件和时间，检查请求结果、状态快照、effects 与资源账本。目标逻辑必须来自真实实现或与它有映射；不能只测试一份理想示例然后宣称固件正确。

每例记录初始 epoch/request/phase、事件序列、丢失点、deadline、期望结果、安全确认、buffer/queue 归属及最大收敛时间。

| 注入 | 必须观察的行为 |
|---|---|
| 命令未到设备，PC 等待超时 | PC 结果不确定；只按幂等/查询契约决定下一步 |
| 设备完成，结果通知丢失 | 查询得到原结果，不执行第二次 |
| 同键同参数/不同参数 | 前者去重，后者拒绝冲突 |
| 旧 boot/phase ACK、乱序失败 | 不推进或反转新操作 |
| 取消与完成交错 | 明确且唯一的裁决，结果稳定，资源无双释放 |
| owner queue 满、timer 投递失败 | 无假 ACCEPTED；本地 deadline 或监督可收敛 |
| ACK 永不来或持续 BUSY | 不超过总预算，不靠心跳续命 |
| 连续 recovery timeout | 预算耗尽后不回到新的无限预算 |
| MCU 与 FPGA 各自重启 | 重新同步，旧 frame 不复活旧请求 |
| 结果缓存满/淘汰 | 明确拒绝/过期，过期不等同未执行 |
| tick/seq 回绕和半空间边界 | 按约定窗口处理，跨 epoch 不比较 |
| 数据满负荷且 STOP 到达 | STOP 的最坏延迟满足测得的预算 |
| DMA stop 失败和迟到 callback | buffer 不提前重用；安全状态不被伪造 |
+| 多通道命令部分失败、共享资源冲突 | 按整体/部分成功契约报告实际效果；重复操作不波及新开通道 |
| 观测过期或快照撕裂 | 不提交配置，不错误宣称安全 |

测试 deadline 前一单位、等于 deadline、后一单位，验证协议选定的同刻裁决。故障注入和随机事件测试记录 seed，并最小化反例。批量随机通过不等同穷尽。

## 分层说清证据

- 结构 lint：只检查显式有限图，guard 和现实调度未知。
- 逻辑测试：在明确事件和时间范围内检查状态演算。
- 模型检查：明确状态空间、队列深度、计数范围、环境故障和公平性假设；输出反例或有范围的结论。
- 平台测试：固件 IRQ/任务压力、FPGA 仿真/CDC、DMA/cache、独立 reset。
- 实机验证：安全动作、时序预算、断电、长稳和复位环。

报告列出实际执行过哪层，未执行层不可写为通过。有限图若忽略了隐藏 flag、guard、retry counter，必须把它标为抽象模型。结构检查出现环不一定错误，例如有限重试；需要显式展开剩余预算或补充计数证明。

## 审查通过条件

高风险路径有可追踪的退出契约和可重放故障用例；没有未解释的等待环、超时恢复环和迟到事件状态反转。平台相关假设被项目证据确认或列为未验证。若只交付设计，给出具体待测项，不能用“已知状态”泛化成“设备安全且一定可恢复”。
