# 技能行为验收场景

这些是 AI 试用场景与人工评审判据，不能当作已经通过的固件验证。使用时把场景、相应技能和最小项目资料交给 AI，保留完整输出再按判据审查；不要把期望结论作为输入的一部分。

本轮静态审查已检查以下规则路径：固件入口按任务选择 driver/DSP/storage/network 参考，测试入口允许直接从单元或回放开始，协议入口限定交互契约，DSH persona 允许直接查询与构建。专项状态规则继续保留。此项是规则和引用审查，不是独立 AI 行为试跑结果。

## 固件、测试与命令工具

| 场景输入 | 期望的决策 | 不应出现 |
|---|---|---|
| ADC DMA 旧数据，现有采样与线协议不变 | 固件技能核对具体 core、DMA 可达性、cache 行与 buffer 交接 | 先要求重写协议或生成完整状态图 |
| 已有 FreeRTOS 工程新增低速 I2C 温度读取 | 依据器件事务、调用上下文和时限选择适度驱动方案 | 强制加 DMA、独立任务或 host 请求事务框架 |
| FIR 滤波耗时过长，误差/延迟要求已给出 | 固件 DSP 参考检查 FPU、算法和周期预算；按需数值回归 | 重新收集全部产品需求或改变公开协议 |
| 修改标定公式，需要 PC 回放 | 直接用测试技能检查元数据、容差和参考依据 | 要求先完成协议设计或状态检查器 |
| SPI Flash busy 阻塞采集 | 检查总线与设备 owner、调度和缓冲余量；保留存储格式 | 为驱动问题增加无关命令和交互状态 |
| LwIP pbuf 泄漏，应用帧不变 | 核对 API 上下文、引用计数与成功/失败路径 | 先重做应用层帧或所有网络状态 |
| 只要求分析现有 map 的 RAM 占用 | 直接使用 map 工具并核对工程内存区域 | 要求提供上位机拓扑或协议规格 |
| DSH 中只要求编译 sensor 工程 | 使用指定工程命令，报告构建结果和日志 | 展开协议设计、自动烧录或更换工具链 |
| 当前只需要纯函数单元测试 | 复用测试设施，选择最小边界和必要输入 | 因未来异步需求预建事件框架 |

## 协议与异步状态专项

| 场景输入 | 期望的决策 | 不应出现 |
|---|---|---|
| 单客户端 START/STOP/STATUS，驱动有界且失败后实际状态可确认 | 明确 stop 含义、重复输入及最小状态表 | 自动加入 HSM、多任务、四视图或请求历史库 |
| 新增上传包中的一个字段 | 检查帧长、版本及相关编码/解码影响 | 全量重写协议或强制重问已知拓扑 |
| 1 通道变 8 通道，同步启停 | 通道配置/选择，沿用采集生命周期 | 枚举全部通道组合或强制 8 个状态机 |
| 部分通道独立启停，共享时钟 | 局部实例与共享资源约束 | 认为 bitmask 消除了全局约束 |
| 标定完成但 ACK 丢失，host 打算换 ID 重试 | 结果不确定、查询与幂等边界 | 将 timeout 当未执行，盲目重做 |
| WAIT timeout→RECOVER timeout→WAIT，每轮刷新 budget | 固定总截止点/下降预算及失败出口 | 仅指出每个节点已有 timeout 就通过 |
| STOP 超时后 mode=SAFE、DMA buffer 被释放 | 要求硬件静止证据、资源生命周期、未知安全事实 | 把赋值或 epoch 检查当成 DMA 已停止 |
| 满队列阻止 timer 投递，owner 卡在 driver | 检查 timer、owner、独立监督各自边界 | 只扩大队列或缩短 timeout |
| 三通道启动中第二通道失败，随后另一个客户端启用新通道 | 按整体/部分成功契约报告实际效果，限定重复/补偿作用范围 | 软件回滚即宣称全部停止，重试影响新活动 |
| 已有 FreeRTOS 工程新增一个同步状态查询 | 沿用上下文与现有基础设施，只做相关改动 | 为追求简单删除 RTOS 或新增 manager |
| IIR 回放均值相同，但输出延迟一段或通道互换 | 核对序列/时间/通道与允许延迟，再比较统计 | 只看平均值就宣称精度未退化 |
| 旧命令仍在支持期，将其返回值改为“已废弃”错误 | 判为兼容性破坏；保留行为或明确迁移 | 认为只改错误码就是兼容的小版本 |
| 队列容量 100、占用 80、突发 10、后续速率 1 项/ms | 无服务余量仅 10 ms，另留裕量并验证调度 | 用空队列的 100 ms 填满时间通过检查 |
| 图有 BUSY 自循环但 timeout 能到终态 | 默认警告仍待解释；严格门禁退出 1 | 忽略 warning 或删真实边以获得 pass |

交付后的实际使用记录应包含输入代码/规范版本、AI 输出、最小修复、实际验证及残余假设。
没有这些记录时，只报告技能结构校验和工具测试，不宣称 AI 行为或实机可靠性已获证明。
